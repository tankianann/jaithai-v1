# M2.1 — Build the Docker PHP and Apache Runtime

**Status:** Planned

**Delivery phase:** Phase 2 — Reproducible local runtime

**Roadmap:** [`../roadmap/roadmap.md`](../roadmap/roadmap.md)

## Outcome

A developer can build and start a documented PHP 7.4 and Apache container that serves the legacy application source with the required web-server configuration and PHP extensions, while all external side effects remain disabled.

## Scope

- Inventory PHP extensions and Apache modules required by the application and its bundled libraries.
- Add a project-level Dockerfile based on the official PHP 7.4 Apache image.
- Enable Apache URL rewriting and the application `.htaccess` behaviour needed by CodeIgniter routes.
- Install only the PHP extensions required for the application baseline, including `mysqli` and any image, archive, or network extensions demonstrated by source use.
- Add project-level Compose configuration for the web service and development source mounting.
- Pass the existing environment contract into the container without committing a populated `.env` file.
- Keep `JAITHAI_OUTBOUND_ENABLED` and `JAITHAI_PAYPAL_ENABLED` false in the local default configuration.
- Add local-development instructions covering build, start, stop, logs, URL, configuration, and known limitations.
- Add a lightweight container health or readiness check appropriate before database bootstrap exists.

## Constraints

- Use PHP 7.4 and Apache.
- Keep CodeIgniter 2.2.2 unchanged.
- Do not add the MySQL service, database schema, or development dataset; those belong to M2.2.
- Do not enable real email, SMS, OneMap, PayPal, cron, or other production side effects.
- Do not treat successful container startup as production readiness.
- Avoid unrelated application refactoring.

## Acceptance Criteria

- The Docker image builds from a clean checkout.
- The running container reports PHP 7.4 and the expected Apache version.
- Required PHP extensions and Apache modules are installed and documented.
- Apache serves `src/` as the document root and honours the intended rewrite configuration.
- The application front controller is reachable from the documented local URL.
- Missing database connectivity is reported as a known M2.2 dependency rather than hidden.
- Local defaults keep every external side-effect integration disabled.
- No secret value is embedded in the image, Compose file, documentation, or committed environment example.
- Build, configuration, and startup instructions are reproducible from the repository documentation.

## Verification

1. Build the image without using uncommitted local files as hidden dependencies.
2. Inspect the container's PHP version, enabled extensions, and Apache modules.
3. Start the service through Compose using safe local configuration.
4. Verify the documented HTTP endpoint and Apache rewrite behaviour.
5. Confirm outbound and payment switches remain false inside the container.
6. Run PHP syntax checks over first-party application code in the PHP 7.4 container.
7. Scan the resulting configuration and candidate commit for secrets.
8. Review the complete milestone diff before commit.

## Exclusions

- MySQL container and database initialization.
- Production or customer data.
- End-to-end order and administration workflows.
- Menu changes.
- PHP, CodeIgniter, or bundled dependency upgrades.
- Production deployment configuration.

## Dependencies and Risks

- The legacy application autoloads its database library, so meaningful application pages may remain unavailable until M2.2 supplies a database service and schema.
- The exact required extension set must be derived from source use and validated during the build.
- The official PHP 7.4 image is an unsupported compatibility base and may require pinned Debian archive handling or other build accommodations.
- Legacy CodeIgniter and bundled library code may emit warnings or fail at runtime even when syntax checks pass.
