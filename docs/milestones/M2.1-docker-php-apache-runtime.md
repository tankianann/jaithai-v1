# M2.1 — Build the Docker PHP, Apache, and MariaDB Runtime

**Status:** Complete

**Delivery phase:** Phase 2 — Reproducible local runtime

**Roadmap:** [`../roadmap/roadmap.md`](../roadmap/roadmap.md)

## Outcome

A developer can build and start documented PHP 7.4/Apache and MariaDB 10.11 containers that serve the legacy application source, accept local database connections, and keep all external side effects disabled.

## Scope

- Inventory PHP extensions and Apache modules required by the application and its bundled libraries.
- Add a project-level Dockerfile based on the official PHP 7.4 Apache image.
- Enable Apache URL rewriting and the application `.htaccess` behaviour needed by CodeIgniter routes.
- Install only the PHP extensions required for the application baseline, including `mysqli` and any image, archive, or network extensions demonstrated by source use.
- Add project-level Compose configuration for the web service and development source mounting.
- Add a MariaDB 10.11 service compatible with the confirmed production database line, without importing schema or data.
- Expose MariaDB only on `127.0.0.1:3307` for local tools such as TablePlus.
- Provide a Docker-only, non-secret `jt-config.php` without reading or replacing the ignored private configuration.
- Keep `JAITHAI_OUTBOUND_ENABLED` and `JAITHAI_PAYPAL_ENABLED` false in the local default configuration.
- Add local-development instructions covering build, start, stop, logs, URL, configuration, and known limitations.
- Add a lightweight container health or readiness check appropriate before database bootstrap exists.

## Constraints

- Use PHP 7.4 and Apache.
- Keep CodeIgniter 2.2.2 unchanged.
- Do not add the application database schema or development dataset; those belong to M2.2.
- Do not enable real email, SMS, OneMap, PayPal, cron, or other production side effects.
- Do not treat successful container startup as production readiness.
- Avoid unrelated application refactoring.

## Acceptance Criteria

- The Docker image builds from a clean checkout.
- The running container reports PHP 7.4 and the expected Apache version.
- Required PHP extensions and Apache modules are installed and documented.
- Apache serves `src/` as the document root and honours the intended rewrite configuration.
- The application front controller is reachable from the documented local URL.
- MariaDB 10.11 is healthy, the web container can connect to it, and the documented TablePlus endpoint is loopback-only.
- Missing schema and development data are reported as known M2.2 dependencies rather than hidden.
- Local defaults keep every external side-effect integration disabled.
- No secret value is embedded in the image, Compose file, documentation, or committed configuration example.
- Build, configuration, and startup instructions are reproducible from the repository documentation.

## Verification

1. Build the image without using the ignored private application configuration as a hidden dependency.
2. Inspect the container's PHP version, enabled extensions, and Apache modules.
3. Start both services through Compose using safe local configuration.
4. Verify the documented HTTP endpoint and Apache rewrite behaviour.
5. Confirm web-to-database connectivity and the loopback-only TablePlus binding.
6. Confirm outbound and payment switches remain false inside the container.
7. Run PHP syntax checks over application code in the PHP 7.4 container.
8. Scan the resulting configuration and candidate commit for secrets.
9. Review the complete milestone diff before commit.

## Exclusions

- Database schema and development-data initialization.
- Production or customer data.
- End-to-end order and administration workflows.
- Menu changes.
- PHP, CodeIgniter, or bundled dependency upgrades.
- Production deployment configuration.

## Dependencies and Risks

- The legacy application autoloads its database library, so database-backed pages may remain unavailable until M2.2 supplies the schema and safe data.
- Additional legacy routes may reveal extension or runtime requirements beyond the source-derived baseline.
- The official PHP 7.4 image is an unsupported compatibility base and may require pinned Debian archive handling or other build accommodations.
- Legacy CodeIgniter and bundled library code may emit warnings or fail at runtime even when syntax checks pass.

## Implementation and Verification

Implemented on 2026-09-30:

- Built the digest-pinned official PHP 7.4 Apache image using Debian Bullseye packages pinned to the 2026-08-01 snapshot.
- Enabled Apache `rewrite` and `headers` plus PHP `curl`, `dom`, `exif`, `gd`, `mbstring`, `mysqli`, and `zip` support derived from source use.
- Added the digest-pinned MariaDB 10.11 service, persistent named volume, health check, web-container dependency, and loopback-only TablePlus port.
- Added a Docker-only, non-secret `jt-config.php` mount with outbound and PayPal switches disabled.
- Added independent Apache and MariaDB health checks and documented local operation.

Verification results:

- PHP reported `7.4.33`; Apache reported `2.4.54`; MariaDB reported `10.11.19-MariaDB-ubu2204`.
- Both Compose services reached healthy state.
- Apache returned `200` for `/__health`, `403` for `/jt-config.php` and the runtime cache/log paths, `200` for the front controller, and the CodeIgniter `404` response for a rewritten nonexistent route.
- The web container successfully connected to the `jaithai` database and queried the MariaDB server version.
- TablePlus binding resolved to `127.0.0.1:3307` rather than all host interfaces.
- The Apache development endpoint resolved to `127.0.0.1:8080` rather than all host interfaces.
- `JAITHAI_OUTBOUND_ENABLED` and `JAITHAI_PAYPAL_ENABLED` both resolved false.
- All 908 PHP files passed `php -l` under PHP 7.4; only known deprecation warnings appeared in legacy CodeIgniter and bundled Dompdf code.
- Gitleaks v8.30.1 scanned the candidate tree with the ignored private configuration excluded and reported no leaks.
- The reviewed milestone was committed as `da93e47`.
