# M3.1A — Existing Menu Image Replacements

**Status:** Implemented

**Delivery phase:** Phase 3 — Catering-menu update

**Roadmap:** [`../roadmap/roadmap.md`](../roadmap/roadmap.md)

## Outcome

Replace the catering landing-page card images for every approved existing menu without changing menu copy, pricing, routes, or ordering behaviour.

## Implemented Scope

- Added 15 cache-safe application assets copied unchanged from the approved processed sources.
- Replaced the Set Catering A–D, DIY Catering A–D, Vegan Catering A–C, Bento, and Mini Party DIY card images.
- Applied the shared non-vegan mini-party image to Thai Celebration, Chaiyo, Sawasdee, and Chokdee in every card occurrence.
- Applied the shared vegan mini-party image to Chaiyo Vegan, Sawasdee Vegan, and Chokdee Vegan in every card occurrence.
- Updated image `alt` and `title` text to identify the menu shown by each card.

The user's list omitted Thai Celebration, but its replacement was included because the approved inventory explicitly assigns it the same source image as Chaiyo, Sawasdee, and Chokdee.

## Exclusions

- Mini Party Set retains `miniparty-set.jpg`; no replacement was assigned to it.
- Sanook retains its existing image; no supplied replacement was assigned to it.
- Vegan Catering Menu D remains pending because the menu and card do not exist yet.
- Deepavali and the three collection-level images remain KIV.
- Retired image files remain in the asset directory but are no longer referenced by the updated cards.

## Verification

- Every implemented destination is a byte-for-byte copy of its processed source.
- All 15 new assets are valid 1280×720 JPEG files.
- A live-browser audit confirmed all 27 affected card occurrences reference and load the approved 1280×720 assets without browser warnings or errors.
- The catering landing-page PHP file passes PHP syntax validation.
- The complete local smoke suite passes all 59 checks for public routes, sessions, cart behaviour, administration, and PDFs.
