# M2.3 — Establish Baseline Smoke Tests

**Status:** Complete

**Delivery phase:** Phase 2 — Reproducible local runtime

**Roadmap:** [`../roadmap/roadmap.md`](../roadmap/roadmap.md)

## Outcome

A developer can run one local-only command to verify the application runtime, public routes, menu rendering, session-backed cart behaviour, database structure, and sensitive-path access controls without placing an order or contacting production and third-party services.

## Scope

- Add a PHP 7.4-compatible smoke-test command that runs from the host or web container.
- Refuse production and other non-loopback targets.
- Refuse non-development configuration or enabled outbound and payment integrations.
- Verify local MariaDB connectivity and expected table structure without modifying rows.
- Exercise representative public, menu, cart, administrator-login, static-asset, missing-route, and protected-path requests.
- Exercise a session-backed add-to-cart round trip without following redirects or submitting an order.
- Document coverage, operation, safety controls, and exclusions.

## Acceptance Criteria

- One documented command runs the complete local baseline and returns a nonzero exit code on failure.
- The same suite passes under the host PHP runtime and the PHP 7.4 Docker runtime.
- The suite cannot target the production URL through its base-URL option.
- All application requests remain on loopback and external redirects are not followed.
- Outbound integrations and PayPal must be disabled before requests begin.
- The suite creates no order, user, option, voucher, feedback, or other database row.
- Public pages, menu form, cart, administrator login, stylesheet, 404 handling, and sensitive-path denial have explicit assertions.

## Verification

Implemented and verified on 2026-10-01:

- Host execution completed 33 checks with zero failures.
- PHP 7.4 container execution completed the same 33 checks with zero failures.
- Production URL input was rejected before any HTTP request.
- All five application tables remained at zero rows after both runs.
- The suite added Catering Menu A to an in-memory session, verified its selected dishes in the local cart, and did not submit an order.
- The application, health endpoint, menu pages, cart, administrator login, stylesheet, 404 route, and protected paths returned their expected statuses and markers.

## Exclusions

- Production testing.
- Final order submission and database-write workflows.
- Authenticated administration.
- Generated PDF and historical PDF verification.
- External integration behaviour.
- Browser and JavaScript automation.
